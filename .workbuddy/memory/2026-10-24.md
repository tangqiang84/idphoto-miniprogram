## 收尾（04:1x–04:3x）：#53 控制台「云端测试」1MB 请求体上限

- **现象**：owner 粘贴 1040KB 载荷点运行 → `AuthFailure.SignatureFailure ... exceeding request size limit, please use new signature method TC3-HMAC-SHA256`。
- **定性**：**不是密钥问题**。云开发控制台走腾讯 OpenAPI 旧签名方式，body 上限 1MB，
  请求被**网关**拦下，根本没到云函数 → 改代码无意义，只能缩小载荷。
- **连带发现自己的锅**：`工具链/make_cloudfn_payload.js` 默认 40 万像素 → 2.1MB，**默认用法必然失败**。
- **修复**：脚本内置硬闸门 `CONSOLE_LIMIT_BYTES=900KB`、`JSON_OVERHEAD=200`、`CHARS_PER_PIXEL=4/3×4≈5.334`；
  超预算自动收敛像素并提示；落盘前出口断言拒绝生成。
  `SAFETY=0.96` 是被自己第一版踩出来的——`downsampleRGBA` 向上取整会膨胀像素（172762 → 360×480 = 172800 顶穿）。
- **产物**：`工具链/cloudfn-payload.json`（353×470 / 864KB，默认，已在剪贴板）
  + `工具链/cloudfn-payload-small.json`（150×200 / 156KB，兜底）。
- **验证**：两份载荷通过 #50 自洽校验；`NODE_OPTIONS= bash 工具链/verify.sh` 全绿（tsc 0 告警 / 单测 142 / 编译成功）。

## 经验沉淀

- **报错里的动词比名词重要**：`exceeding request size limit` 才是根因，`SignatureFailure` 只是被顺带触发的文案。
- 区分**控制台限制**（1MB）与**运行时限制**（`callFunction` 5MB）；云端测试跑不通 ≠ 线上跑不通。
- 生成类工具的**默认值必须先自跑一遍**——坏默认值会让使用者误判成环境问题，排查成本极高。
