## 使用入口

在项目根目录执行；每次都会新建唯一运行目录。

```bash
bash 工具链/verify.sh                  # 开发：单测、类型、Lint、隔离构建
bash 工具链/verify.sh --quick          # 开发快速检查：不构建，不假称构建通过
bash 工具链/verify.sh --no-build       # 同上，保留兼容参数
bash 工具链/verify_all.sh              # 里程碑：再检查覆盖、六工具冒烟、真实素材批验
bash 工具链/verify_all.sh --no-ide     # 明确跳过IDE，必需未验使总体BLOCKED/退出3
bash 工具链/verify_all.sh --no-build   # 必需构建未验，BLOCKED且不启动依赖其产物的步骤
bash 工具链/verify_all.sh --quick      # 里程碑的必需项被跳过，不能返回全量通过
```

两个兼容Shell入口都直接`exec`同一Python调度器，避免管道和`PIPESTATUS`丢失真实退出码。core单测每次运行只执行一次，不为统计数量再跑一遍。`--strict`保留兼容，里程碑本身已经严格。

Shell入口固定各自检查范围，调用时附加`--profile development`不能把里程碑降级；需要自选范围可直接调用Python调度器，报告会明确记录所选范围。

可选参数：`--output-root <父目录>`（只在其下新建run，不复用旧目录）、`--timeout <每步秒数>`（默认600）、`--ide-wait <0–60秒>`（默认30，IDE步骤串行）。未知参数或非法值退出2。不会替用户改凭据、部署或发布。

输出父目录不能位于源码、工具或素材树中，防止快照递归复制自身；NaN/无穷等非法时间参数也会拒绝，不启动检查。

## 状态与退出码

| 状态 | 含义 | 总体处理 |
|---|---|---|
| PASS | 当前范围内的检查确实执行，命令与必要证据满足条件 | 仅声明所选范围 |
| FAIL | 产品/检查失败、未知非零退出、成功但产物缺失或报告矛盾 | 退出1 |
| BLOCKED | 覆盖缺口、IDE不可用、依赖未就绪、超时或必需项未验 | 退出3 |
| SKIPPED | 用户显式跳过或上游未通过，本项未执行 | 必需项导致总体BLOCKED；已有FAIL时退出1 |
| N/A | 开发范围不包含覆盖/IDE项，写明适用性理由 | 不把N/A计作执行通过 |

开发`--quick`允许缩小检查范围，所以可以返回“开发范围PASS”，报告同时记构建SKIPPED；里程碑的相同跳过参数不改变必需项，不能得到PASS。总结果优先FAIL，其次必需项未通过为BLOCKED。用法/输出目录错误为退出2。

覆盖工具的已知退出1解释为缺口BLOCKED，未知退出码FAIL。批验退出3解释为IDE不可用；其他非零（含业务退出4）均FAIL。批验即使退出0，也检查本轮`results.json`：无样本、未评估、环境受限或待审查N/A均不判里程碑通过；缺报告、计数矛盾、逐项失败却汇总成功均FAIL。N/A在批验中先阻断并要求逐项审查，不能泛化豁免硬指标。

## 隔离构建与报告

- 运行目录：`docs/验证记录/verify-runs/run-时间-随机ID/`，全部新建，旧目录不清理。
- 只复制执行所需源码/配置/工具/测试素材；排除`.env*`、密钥/证书、私有配置、历史`dist`、报告和`_tmp`。依赖目录以链接复用，不安装小程序依赖。
- 构建在`workspace/idphoto-miniprogram/dist`；**不会更新原项目dist，也不会自动刷新原开发者工具中的版本**。真实调试需打开报告中的隔离工程，或另行经授权更新开发目录构建。
- 冒烟和批验也在快照运行。旧脚本固定路径写入只发生在本轮快照内，不覆盖原截图、`LATEST.txt`或旧覆盖矩阵。覆盖检查使用只读`--check`。
- 构建退出0还必须有本轮`dist/app.json`，随后记录产物文件哈希和构建ID。历史dist不会被复制进去冒充新构建。

| 证据文件 | 内容 |
|---|---|
| `report.json` | 每步命令、退出码、状态、必需性、理由、耗时和日志；总体状态与限制 |
| `inputs.json` | 快照输入文件SHA-256；报告绑定其哈希 |
| `build-files.json` | 当前构建文件哈希；哈希作为build_id |
| `unit/types/lint/build/...log` | 本轮检查输出，敏感字段和长编码脱敏 |
| `workspace/batch-products/` | 本轮批验成品及结果（仅真正执行批验时存在） |

元数据记录来源Git提交、工作区状态/差异指纹、Node/npm/Python版本、时区、TraceID、素材集哈希、构建ID和适用范围。未运行IDE/云业务时不捏造provider/source；真正批验时定位本轮结果中的backend/source。工作区有未提交文件时仍可运行，不能把整个差异都归因于当前任务。

## Lint 基线与安装

用户已批准隔离依赖：`工具链/lint/package.json`及其独立lock固定ESLint 8.57.1、TypeScript parser 8.72.1、TypeScript 5.9.3、React Hooks插件5.2.0。小程序dependencies/devDependencies及package-lock不变，只新增scripts入口。

安装位置为`工具链/lint`，首次安装按独立lock执行`npm ci --ignore-scripts`；不要在小程序目录为此安装包。重装会改动隔离依赖目录，按用户对覆盖操作的授权执行。缺失时检查器返回3，不当成“无错误”。版本兼容范围已核对[typescript-eslint官方说明](https://typescript-eslint.io/users/dependency-versions/)，并验证本地安装结果。

```bash
cd idphoto-miniprogram
npm run lint                # JS/TS/TSX、云函数JS及工具JS；131文件基线
npm run test:lint           # 6例：三种语言通过、debugger/重复键/语法错误被拒绝
npm run test:verification   # 隔离故障夹具；所有证据保留，不删除目录
```

初始规则有语法检查、debugger、重复参数/键、不可达代码、typeof合法性、finally安全及Hooks调用规则。不引入格式化和全项目重排，不自动`--fix`；类型正确性仍独立由tsc检查。旧代码的Hooks依赖注释需要插件定义，因此插件已显式安装；本任务没有借此开启全量依赖建议或改动业务Hook。

Python检查器/测试由AST与实际unittest校验，Shell入口由`bash -n`校验；不把ESLint称为Python/Shell完整Lint。

## 故障夹具与剩余边界

`工具链/test_verify_runner.py`将相同入口/调度器复制到新建夹具工程，用受控npm/node替身模拟真实退出码、超时和产物。真实源码与dist有哨兵保护，重复运行验证旧报告未变；夹具保留在`工具链/_tmp/rc02-fixtures-*/`并写`summary.json`，禁止先删后跑。

覆盖映射是否真正对应需求归RC-03；修好入口不代表旧断言已正确。业务交互/模型/换装问题仍由RC-04至RC-12处理。当前里程碑运行被已有覆盖缺口阻断，是闸门正确工作，不得通过修改阈值或把缺口改人工来获得绿灯。
