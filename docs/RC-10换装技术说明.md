# RC-10 换装技术说明

T1 证件照和 T3 换装共用 `idphoto-miniprogram/src/services/t1Processing.ts`。此文描述三款研究模板的现行路径。架构中早期的双肩相似变换、肩颈贴图与原生衣物推理记录属于历史方案。

## 处理流程

1. 使用用户确认的裁剪窗建立工作画布。云端人脸、姿态、服装解析和领口拟合使用同一份长边至多 768 px 的等比图。坐标与掩膜分别映射回工作空间，分类掩膜使用最近邻缩放。
2. 原生检测已确认多人时直接拒绝。研究模板统一用自有 `facepoints` 的 MediaPipe 478 点。将两个嘴角的平均纵坐标加面框高度的 0.21 倍，再限制在面框高度的 78% 至 100%，得到领口搜索的颏部起点。该值仅用于拟合，裁剪使用原有度量。来源不匹配、关键点不可用或未同意上云时停止换装。
3. 姿态服务返回实测双肩，`checkComposition` 校验单人、双肩和构图。双肩决定照片是否适合换装。领口由可见颈部与模板透明开口匹配。
4. `suitparse` 返回 18 类像素标签，客户端提取原衣和背景掩膜。`suitfit` 使用单独的六类概率模型搜索领口几何。客户端核对返回的尺寸、模板 ID、模板与模型摘要及几何范围。
5. `src/core/suitCollarCompose.js` 在工作图上清除旧衣、采样高清模板并合成。脸部关键点凸包和额头保护区要求 RGBA 与透明度差异均为零。脸框差分保留作诊断。任务过期或授权撤回时，处理会话丢弃结果并禁止后续操作。

## 云端契约

| 服务 | 输入与返回 |
| --- | --- |
| `facepoints` | 缩图及动作授权。返回单脸坐标、面框、模型摘要与来源。Python 3.11，512 MB。 |
| `matting` 姿态分支 | 缩图及动作授权。通过现有百度姿态接口取得双肩坐标与分数。 |
| `suitparse` | 缩图及动作授权。返回与输入图同尺寸的类别掩膜。Python 3.11，1536 MB。 |
| `suitfit` | 缩图、同尺寸透明度、面框与颏部纵坐标、模板 ID 和动作授权。返回 `left`、`top`、`scale`、模板坐标系内的 `protectY` 及模板尺寸，附来源、摘要和 TraceID。Python 3.11，1536 MB，超时 30 秒。 |

`suitfit` 请求使用 `purpose=suit_collar_fit`，服务校验上云与换装授权字段、图像尺寸、载荷长度及模板白名单。响应失败使用结构化错误，例如 `SUIT_NECK_UNAVAILABLE` 或 `SUIT_COLLAR_UNSUPPORTED`。诊断日志只记录阶段、错误码和 TraceID。请求中的区域、留存和训练字段是应用契约，相关承诺以部署和服务证据为准。

## 导出和部署验收

换装 JPEG 默认质量为 0.95。T1/T3 的标准档实际文件低于规格下限时，依次尝试 0.97 和 1.0，最终按真实尺寸、格式和规格重新自检。重新生成后旧自检和导出归属失效。高清档继续沿用印刷档规则。

独立部署包包含固定 ONNX 权重、模板及其摘要、运行依赖和许可文本。部署包由本地证据目录保存。更新时应核对模型、模板版本与客户端所接受的摘要。使用 `node --test 工具链/tests/rc10_client.test.js 工具链/tests/suit_safety_page.test.js` 检查接口、授权、T1/T3 拒绝路径和导出，使用 `python3 工具链/verify_runner.py --no-ide --output-root <新目录>` 执行核心测试、类型、Lint 与隔离构建。
