## 发布检查与恢复

1. 绑定提交、构建文件摘要、开发版号和素材集版本。若同源码重新构建的产物摘要变化，保留两套身份并区分记录。
2. 分别记录核心回归、覆盖、原型、导出、iOS、Android、云链和后台材料。运行 **node 工具链/rc12_release_gate.js <证据清单.json> <独占结果.json>**。脚本核验候选身份、证据类型和文件摘要，验收人仍需核对证据内容。退出码 0 表示清单门禁通过，1 为明确失败，3 为证据缺口，2 为输入输出错误。
3. [真机用例](../真机冒烟S1-S8操作清单.md)记录机型、系统、微信、基础库、版本、素材标识、操作耗时、权限拒绝和撤回、旧结果失效、保存与再次编辑。云链使用具备对应上传授权的素材。
4. 后台核对新名称、备案、头像、简介、隐私指引和候选版本，登记审核与发布的实际状态。前置不满足时保留线上版本和失败证据。
5. 若线上发生阻断，先核实当前线上版本、上一稳定版本和涉及的云函数。按平台实际提供的恢复入口恢复已确认稳定版本，再复核首页、T1 导出与受影响功能。云端改动单独检查前后兼容，恢复操作须按发布授权执行。

当前阻断包括双平台真机、全量需求覆盖、云端整链与后台材料一致性。开发测试全绿不能替代这些证据。

2026-11-23 后续源码已修正首页和授权隐私披露，已上传开发版仍以本页所列构建摘要为准。将披露修订纳入后续候选时，重新绑定构建身份，并对照[隐私披露更新](../用户隐私保护指引与隐私政策.md)核实后台及第三方共享材料。
