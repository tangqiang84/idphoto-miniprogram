# RC-04 统一处理会话

日期：2026-10-28。需求依据：PRD B2/D3/E1/H2/AC12/FLOW-1及原型s_crop等，需求承诺不变。RC-01现状证据更新为v1.4。

## 范围和结构

新增框架无关的`core/processingSession.js`与类型声明，使用`useProcessingSession`管理页面生命周期，先接入T1。原`prepareWorkCanvas`、抠图、美颜、换装与合规算法继续复用；T2/T3/T5迁移由RC-07进行。完整逐步显示/返回/跳过及美颜独立确认由RC-05完成。

原实现将参数放在多个useState，重跑调用默认裁剪窗为null，也没有异步版本校验。本次将处理参数统一到会话，通过版本化任务保护现有平台边界；没有重写图像算法或引入依赖。

## 参数与坐标

| 参数 | 内容与规则 |
| --- | --- |
| source/sourceId | 原图临时路径、原始宽高、复杂背景提示；每次选图更新sourceId，不因路径相同复用旧图 |
| specId | 9种现有规格；变化后生成新比例建议窗，必须重新确认 |
| cropWindow/cropConfirmed | 原图左上角坐标x/y、原图像素宽高w/h；只有显式确认后才允许下游处理 |
| beauty | enabled及smooth/whiten/brighten；拒绝其他变形参数 |
| bg/suit/dpi | 底色键、换装意图与模板ID、300/600档位；均从任务参数快照读取 |
| consents | 当前授权集合；仍沿用现有入口授权规则，按动作拆分由RC-06完成 |
| revision/traceId | 参数/取消版本及任务唯一标识；任务输入为独立冻结快照 |
| selfChecked/output | 当前生成结果的自检与结果；参数变化或重新生成使其失效 |

T1选图后只调用本地检测/构图生成裁剪建议，不抠图、美颜、请求上云或成品导出。建议失败可手动确认默认居中窗，不能把建议任务认作成品成功。用户拖缩后以确认的原图坐标窗传入prepareWorkCanvas；改变dpi不会丢弃已确认窗。像素档位带来的舍入/有效像素/实际文件验收仍归RC-08。

## 状态转换表

| 当前状态/动作 | 下一状态 | 行为 |
| --- | --- | --- |
| empty → 选图 | crop → processing（crop-suggestion）→ crop | 清旧图结果，本地建议后等待确认；任务不得代替确认 |
| crop → 拖缩/改规格 | crop | 更新原图窗或按新比例生成窗，确认失效 |
| crop → 确认 | ready | 记录确认版本，T1现有处理入口允许启动 |
| ready/success/error/cancelled → 执行处理 | processing | 锁定参数快照，清旧自检和会话输出 |
| processing → 完成 | success | 仅当前版本可提交结果；阶段记录crop/beauty/matting/suit/export/precheck |
| processing → 重复点击 | 不变 | SESSION_BUSY；不会新发同一任务，重复确认也不会取消重发 |
| processing → 参数变化/换图 | ready/crop/empty | 取消旧任务，旧返回不得回写或进入下个调用 |
| processing → 超时/失败 | error | 结构化原因码+可读信息+TraceID，保留当前参数供重试 |
| 任意状态 → 用户取消 | cancelled | 保留参数，清输出/自检；可重试 |
| 页面卸载 | 不再接收动作 | dispose取消任务、移除订阅，旧返回不得更新页面 |

此处阶段记录用于处理任务有效性与诊断；不代表原型的独立步骤屏已经完成。

## 失效表

| 变化 | 裁剪窗/确认 | 结果、预审、自检与缓存 |
| --- | --- | --- |
| 新照片 | 新图新窗，未确认；美颜/换装恢复默认 | 全部失效；保留规格/底色/dpi/授权偏好 |
| 新规格 | 按新比例生成窗，未确认 | 全部失效；明确提示重新确认 |
| 拖缩裁剪 | 新窗，未确认 | 全部失效 |
| 美颜/模板/换装意图/dpi | 保留已确认窗 | 全部生成结果与自检失效，重新处理 |
| 底色 | 保留已确认窗 | 输出/预审/修补预览/自检失效；有效处理像素缓存可只重合成 |
| 授权变化 | 保留裁剪几何 | 取消旧任务并清输出/缓存；重新按当前授权检查 |
| 再次生成/修补 | 保留参数与裁剪 | 旧自检失效；修补alpha写回有效缓存，后续换底不丢修补 |

底色重合成若复用已换装像素，会恢复实际“已换装”标识，并再次要求自检；不能因缓存重用跳过自检。换装配置面板不依赖旧预览仍可见，避免改模板使旧预览失效后无法继续应用。

## 异步与错误

`execute`为任务建立revision/traceId；`task.call`在每个异步平台边界前后检查有效性，`task.check`守卫同步后续调用；云适配器也单独包裹，旧segment内部若迟到才尝试上云会被拒绝。参数变化、取消、卸载会中断等待，旧任务即使返回也不能提交。支持注册SDK中止回调；现有SDK无中止能力的请求只丢弃结果，已经发出的请求不能撤回。

总任务默认90秒超时，原图片/云服务超时仍保留。错误以SESSION_*原因码及可读描述返回；内部日志只记TraceID/阶段/原因码，不输出原异常、照片或密钥。重复点击、取消、失效不伪装成产品成功。

T1裁剪前探针现在应为PASS；T2/T3/T5保留既有FAIL，不删除或放宽断言。全部76条需求仍有主验收/人工或部署证据缺口，产品里程碑不能通过。具体执行与限制见[RC-04验证报告](验证记录/RC-04-20261028-01/报告.md)。

## 完成性复核补齐（2026-10-28）

首次交付已保护处理任务回写，但保存/冲印仍可能使用闭包捕获的旧预览与旧自检。本轮反例复现同参数重新生成后的旧回调仍发起保存；已统一到当前结果校验：revision、traceId及具体成品路径均须匹配，并读取当前会话自检，而非旧回调中的布尔值。结果内保存实际suitApplied，处理/修补/底色重合成均传递该标志，冲印入口也遵守自检失效规则。

参数不变的重新生成会更换任务标识，不能只靠revision判断。已发出的保存/跳转请求不能撤回；迟到通知同样检查当前任务和结果，避免通知归到新任务。镜像自查、整体预审门控及完整逐步界面仍由RC-05等原定任务接续，不据此认领全量产品通过。

当前完成性以[复核报告](验证记录/RC-04-20261028-02/复核报告.md)为准；首次报告保留。模型仍8项，页面控制回归增至7项，共15项RC-04专项；控制/SDK替身不替代真实成品或微信验收。

同类边界补充：旧AlphaPatch回调也不可用旧patchBase画布启动新任务；修补先校验revision/traceId/具体输出绑定，再允许加工。修补前不要求先自检，重新生成的换装结果仍须重新自检才能保存/冲印。SDK保存/跳转失败仅记录原因码和对应TraceID，不记录原始异常或成品载荷。页面控制反例现7项，包含旧修补拒绝和当前修补正例。
