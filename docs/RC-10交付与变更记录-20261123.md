# RC-10 交付与变更记录（2026-11-23）

**开发已交付，任务待真机/人工验收。** 本记录汇总 T1/T3 换装、云服务、拒绝路径、高清合成和导出的开发结果。快照基线为 `44d246e5`，实际开发验证覆盖当时未提交的工作区代码。

| 阶段 | 已实施变更与验证结果 |
| --- | --- |
| 模板与姿态 | 接入三款用户授权的研究模板，保留来源、许可及规格资格检查。百度实测双肩用于姿态门禁，默认估算不计入通过。 |
| 云服装解析 | 自有 `suitparse` 使用 18 类模型，部署为 Python 3.11、1536 MB。获批的单次真人解析与本地类别图逐字节一致。早期低内存失败记录保留；当前账户可配置内存。 |
| 人脸与工作尺寸 | 自有 `facepoints` 提供 MediaPipe 478 点。云识别共用长边 ≤768 的等比图，返回坐标及遮罩映射回工作图；保留已确认裁剪。 |
| 原方案与改型 | 旧双肩相似变换仍出现领口与颈侧构图问题。参考 HivisionIDPhotosPro 的领口适配思路，采用真实六类概率搜索透明开口；硬标签冒充概率的实验失败并弃用。 |
| 领口生产化 | 部署自有 `suitfit`（Python 3.11、1536 MB、30 秒），返回几何参数。端侧使用高清原图及模板合成，清理旧衣并保护脸部 RGBA 和透明度。 |
| 遮挡回归 | 初版用脸框底边作为颏部起点，历史遮挡样本在白色模板上误通过。改用真实嘴角推算后，Linux 生产包复放中正常样本三款通过、遮挡样本三款拒绝。 |
| 真人云验证 | 在单次授权内验证黑色模板，云端几何与本地 Linux 生产包逐字段一致。使用该响应在本地合成 1152×1536 图，脸部保护区差异 0。该次调用未调用百度，也未重试。 |
| JPEG 与规格 | 50 张本地 JPEG 的格式和尺寸正确，4 个组合按规格资格拒绝。美签 300 档遇到体积不足时提高编码质量并继续执行原有自检。开发者工具实际输出从 53,846 字节升至 61,623 字节，保持 600×600 JPEG。 |
| 来源统一 | 模拟器无法启动 VisionKit。最终版本让研究模板统一使用已授权的 facepoints 嘴角坐标；端侧已检出多人直接拒绝，关键点不可用则停止换装。原生检测继续服务基础流程。 |
| 回归与交付边界 | 161 项工具链测试通过，核心测试、类型检查、Lint 与微信小程序隔离构建通过。真实微信编码探针、Linux 真人回放、云探针和页面替身测试分别记录。最终构建的真实页面全链路及跨样本视觉验收仍缺证据。 |
