## 结论

微信原生ONNX推理路线有官方依据；当前MODNet社区导出文件在微信引擎中的兼容性尚未成立。此前把CPU ONNX Runtime执行成功作为继续真机接入的主要前提，却未先完成微信模型兼容基准和算子属性核对，这是方案验证顺序的实质缺口。停止重复调参和扫码，先完成可证伪的兼容实验设计。RC-09继续阻塞，不能宣布端侧模型选型完成或有效推理成功。

## 官方依据与实现核对

本轮直接获取微信官方Markdown文档，另保存教程HTML及解压文本。浏览工具此前读取失败不代表官方文档不可获取。

- [AI使用指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/inference/tutorial.html)：微信将ONNX自动转换为自研引擎格式。官方示例使用mobilenetv2-12.onnx；ONNX Runtime CPU能执行不等于转换后的微信引擎数值等价。
- [createInferenceSession](https://developers.weixin.qq.com/miniprogram/dev/api/ai/inference/wx.createInferenceSession.html)：支持本地.onnx；precisionLevel=4为FP32存储、FP32计算、开启Winograd、关闭近似math；allowNPU=false、allowQuantize=false有效。typicalShape为对象，动态轴可以指定输入典型形状。当前配置符合该接口，不能仅因动态轴判定违规，也不能把typicalShape当成静态图转换。
- [Tensor](https://developers.weixin.qq.com/miniprogram/dev/api/ai/inference/Tensor.html)及[run](https://developers.weixin.qq.com/miniprogram/dev/api/ai/inference/InferenceSession.run.html)：Tensor使用shape、type、ArrayBuffer；输入名与模型对应，在onLoad后运行。当前适配的input/output、NCHW、ArrayBuffer、加载事件均与公开契约相符，未发现足以解释全部非有限输出的接口字段错误。
- [算子支持表](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/inference/supports.html)：CPU列有InstanceNorm、Resize2D、Shape等；列的是引擎算子类别，并非所有ONNX版本、属性及组合的逐项保证。特别说明GPU推理暂未对外开放，不能根据教程概述自行规划启用GPU作为解决办法。

## 模型与已有证据

只读解析现有文件protobuf字段，结果见graph-inventory.json（非完整ONNX checker）：摘要07c308cf0fc7e6e8b2065a12ed7fc07e1de8febb7dc7839d7b7f15dd66584df9；默认域opset 11，487节点、19种算子。16个InstanceNormalization的epsilon约1e-5；9个Resize为linear、pytorch_half_pixel；另有Shape/Gather/Expand等动态形状链。

这些算子可映射到官方公开的支持类别，未据此发现一个可以直接宣布“不支持”的算子。InstanceNormalization的epsilon处理、Resize属性及动态形状转换是待验证点，均不是已经确定的故障源。全零输入可能产生零方差，但标准epsilon处理应保持数值有限，不能删除这个失败输入来获得通过。

手机普通预览证据：output、float32、[1,1,512,512]、1048576字节均正确；262144个值全部非有限。相同模型和全零输入的CPU对照输出有限。故障已从远程超时缩小到模型执行/引擎转换/数值或数据边界的兼容问题；现有证据不足以区分具体根因，也不足以断言微信不支持MODNet。21122ms为整段累计时间，不是纯推理耗时。截图及CPU证据分别见../RC-09-output-contract-20261105/非有限输出定位.md、../RC-09-context-audit-20261105/cpu-synthetic-zero.json。

即使修复数值问题，授权照片RC09-USER-10暗部人脸/发丝破洞的既有CPU视觉失败仍须独立解决，不能以原生运行成功覆盖质量缺陷。

## 修订执行门槛

1. 先准备微信官方教程所指的MobileNetV2浮点示例及固定输入CPU期望，记录精确文件摘要、来源、设备/基础库。用途仅为验证原生环境，分类成功不计抠图验收。
2. 本地准备小型ONNX对照：InstanceNormalization零方差与非恒定输入、相同Resize属性和动态形状链。逐项建立CPU参考和有限值断言，验证后集中提供一次手机测试包。已失败样本保留，禁止降低校验门槛。
3. 若官方基准成功而最小图失败，定位到转换/属性兼容；若最小图均成功而MODNet失败，继续按子图边界定位，不依据猜测调整epsilon或精度。静态512图作为独立实验，保存新文件/新摘要，必须与原图CPU对照，保留原始资产。
4. 数值对照通过后，再验证授权真实照片及视觉缺陷、耗时/资源、撤回和回落，分别记录iOS/Android适用证据。现有云开发及已接入服务另行验收，不为此新增独立云服务。
