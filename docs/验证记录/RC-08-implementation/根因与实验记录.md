# RC-08 根因与可证伪实验

2026-11-04。所有失败日志保留，不通过改产品阈值获取通过。

1. KB边界：204801/1024=200.0009765625，旧调用取整成200，错误通过。实验使用204800、204801及20479字节；将原始字节/1024直接传校验，300严格、600机构项提示、T5显式上限仍严格。
2. 档位证据：旧DpiStep有效裁剪缺失时回退工作图。新组件测试给6000×8000原图、300×420有效窗、1600×2200工作图，仍提示不足；缺失有效窗明确未知；有1200×1600有效窗但处理仅300×420时另警告处理不足。像素足够不再表述为“实拍像素”。
3. 规格/几何测试初始错误：6寸一寸误写8张固定期望。独立毫米实验：(148−6+2)/(25+2)向下取整为5，(98−6+2)/(35+2)为2，总10张。参考表“约8–10”是示意，不是8张硬指标；改正独立期望与注释，产品count没有修改。
4. 两轮排版测试未通过后停止盲改。第一轮未找到芯片，根因测试文本提取器丢数字；补数字提取后进入第二个断言，发现照片旋转没有执行。检查bestTiling四组合顺序：纸旋转不转照片与照片旋转不转纸的count等价，而前者先出现、相等不替换，故当前数据不能选photoRotated=true。可证伪实验：读取6寸二寸计划为纸旋转true/照片旋转false、2×2、1205×1795；实际页面导出按此核验，源裁剪比例仍35/49。因此没有证据将“照片未旋转”认作当前可达缺陷。新增显式旋转绘制仅保证后续该组合可达时语义正确，不认领实际运行覆盖。未来算法改变须补该分支的可达验证。
5. 文件不符测试从旧FLOW_HARD_CHECK变为会话安全包装SESSION_PROCESS_FAILED：落盘核验在生成结果前拒绝，不再产生可消费成品。保留会话现有错误契约；内部EXPORT_DIMENSION/EXPORT_FORMAT由校验单元独立断言。
6. 首次SDK矩阵启动时开发者工具仍在编译taro.js，cases=0，保留截图。第二次在编译完成后运行，报告逐项更新；不将首轮环境失败计为产品或负例通过。
7. 登记脚本首版误写可读基线的验收列，被语义一致性闸门拒绝；恢复每条独立验收文本，并按现状列重建证据链接，机器/可读基线再次校验通过。

尚未以本轮测试证明神经模型内部输入尺寸/视觉质量、真实打印机误差或双平台实体机。分割入口像素与模型内部输入不是同一指标。

8. SDK第二轮22个成功后，12寸实文件为3000×3602，独立测试误期望横纸3602×3000。几何单测已允许相纸旋转，但SDK固定常量漏了该路径。独立毫米计算：301×250可打印区留边后，横纸11列×6行=66，竖纸9列×8行=72，故旋转纸张是正确行为。仅修正SDK/独立读图器该项期望为3000×3602，产品与容差不变，原失败文件和截图保留。

9. T5二次字节核验反例发现：旧工作流已阻止保存，但hard-check失败仍保留finalResult对象。修复为先提取失败项、清空成品再返回结构化失败；同时按工具改写检查项后重新计算report.pass/suggestions，避免“检查失败但汇总通过”的不一致。保存动作与对象状态一起断言。
