## 动作矩阵

| 工具/动作 | 必需授权 | 拒绝时 |
| --- | --- | --- |
| T1/T2/T3/T4选图、打开相机、读取回传照片 | faceLocal | 不调用相册/打开相机，不读取迟到照片 |
| T1/T2/T3抠图、美颜等本地处理；T4只读检测 | faceLocal | 不启动相关新处理 |
| T1/T2/T3云端抠图增强 | faceLocal + faceCloudEnhance | 保留可用本地结果；本地低置信时提示质量限制，不强迫上云 |
| T1/T3本地职业装合成 | faceLocal + suitSwap | T1可跳过；T3可先取图，需单独同意后点击“应用换装” |
| T1/T3云端姿态信号 | faceLocal + suitSwap + faceCloudEnhance | 不编码/上传姿态区域，使用可用本地信号；适配不足如实拒绝/提示 |
| T5规格变换、T6拼版选图及处理 | 无人脸授权 | 不强加人脸授权，原有文件/镜像等检查保留 |

`requiredConsents(tool)`用于列出授权设置项，不再代表每个动作都必须集齐。`buildConsentRecord(tool, granted, action)`默认local，可指定collect/cloud/suit/pose；未知工具或动作拒绝，T4云动作拒绝。旧的“勾齐T1/T2两项、T3三项才能选图”说明只适用于历史版本。

页面授权默认不勾选。用户可在各功能页授权区取消勾选；T1基础/云授权区各步可达，换装同意在换装步骤取得，离开换装步骤后也提供撤回入口。授权来自明确勾选，未默认开启。微信自身隐私接口授权与本产品动作授权分别处理。

## 撤回与异步边界

- T1沿用processingSession：授权变化增加revision，停止当前会话结果回写、清除预览/最终成品/自检及预审凭据；撤回基础授权同时移除页面原图输入。可选授权变化保留已确认裁剪，返回需重新处理的步骤。
- T2/T3/T4使用共享consentSession和useActionConsent，授权变化先同步更新版本、清理结果/缓存，再触发React更新。基础授权撤回后T2/T3源图引用也清空，T4检测报告清空。此处只补授权保护，完整处理会话迁移归RC-07。
- 每次相册、相机、处理任务捕获授权版本。`token.call`在实际调用前后检查，防止旧闭包、迟到返回和“撤回→重新授权同一集合”恢复旧任务。保存回调绑定生成结果时的授权版本，不能拿新授权消费旧图。
- 选图hook检查相册返回、图片信息、文件大小、质量评估之后的授权版本；相机撤回后隐藏预览，迟到拍摄回传不会读取图片。页面卸载也使令牌失效。
- 质量提示与其评估授权版本绑定：撤回后隐藏，重新同意不恢复；图像加载迟到时，先检查权限再绘制/读取像素。T1将会话授权同步至consentSession，选图/质量评估不以普通图像处理revision作授权版本，合法新评估仍显示。
- CloudBase抠图适配器及保留的HTTP云工厂默认拒绝无授权上下文的调用；页面注入的上下文同时检查当前任务/授权版本及cloud动作。姿态服务缺pose权限时结构化返回本地降级，实际请求返回后再检查一次。

平台支持的会话取消沿用RC-04；CloudBase调用未提供可可靠中止的句柄，因此**已发出的请求不能撤回**，只能拒绝其返回并阻止下一次上传。不会声称清除了已发送到远端的数据或用户相册里已保存的照片。完整销毁/留存承诺仍需RC-11及部署证据。

## 验证方式与限制

- 两项core测试覆盖动作矩阵、未知动作拒绝、撤回/重新授权与在途调用丢弃。
- `工具链/tests/consent_actions.test.js`执行实际页面/选图hook和旧页面处理代码，覆盖T1至T4基础拒绝、迟到选图/拍摄、旧闭包、在途处理、T3独立换装同意及T5/T6无脸授权；SDK/图像服务按用例替换。本地低置信样例使用真实segment，断言零上传且返回质量限制。
- `工具链/tests/consent_network.test.js`执行真实cloudFnAdapter/HTTP云工厂/poseService源码，SDK调用计数分别验证无权限零调用、授权可调用、撤回丢弃。无真实网络请求或收费调用，不等同真实模型/境内/留存的部署验收。
- 页面测试额外验证T1最终成品撤回后旧保存回调失效，重新处理后新结果可保存。
- 微信开发者工具在全新禁云副本中，以REAL-111固定授权样本实际走“仅本地授权→逐步导出→授权变化→撤回→重新同意”，截图/真实JPEG与构建绑定。SDK事件不等同真人手势或实体手机。
