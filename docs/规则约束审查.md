## 结论

现有规则覆盖了最小改动、资产保留、授权、模型许可和关联回归，但尚不足以防止反复开发。主要问题是规则分散、历史口径相互矛盾，以及完成标准未形成可靠的执行闸门。继续追加事故条款不能代替修复流程与验收工具。

新增根目录 `AGENTS.md` 作为开发入口；整改按 `docs/整改开发任务.md` 推进。此次不改写旧台账和原型，不把历史通过结论直接继承到新验收。

## 需要收敛的旧规则

1. **“只增不删”与维护成本**：本轮继续严格保留资产。后续废弃工具先标 deprecated，注明替代入口；删除仍须用户逐项确认。保留历史不等于继续把旧入口作为推荐命令。
2. **“不能新增依赖”与“不要随意增加依赖”**：目前不安装任何依赖。Lint 任务先盘点可复用工具；确需开发依赖时写清方案和构建影响，再按适用规则取得确认，不能借 Lint 顺手重排依赖。
3. **“全量回归”与迭代效率**：开发时按影响面运行；共享节点跑关联工具；里程碑执行完整验收。快速检查不得命名为全量验收。
4. **“文档同步”与多份状态漂移**：需求文档描述期望，技术文档描述实现，任务表描述进度，报告记录证据。采用链接引用，避免把“当前完成数”复制到多份指南。
5. **禁止覆盖与正常编辑**：本轮只新建文件。后续业务修复、构建清理旧 dist、脚本覆盖报告/指针等，执行前须依据用户全局规则取得相应确认；不能假设脚本自动执行就不算覆盖。
